01
Datetime Parsing & .dt Accessor

"Before Pandas can work with time, it needs to know a column is time — not text."

When you load a CSV, Pandas reads date columns as plain strings. As long as a date is a string, you cannot sort by it, slice a year out of it, or do time-based math. Step one in every time series project: convert to datetime.

# Default — Pandas reads dates as strings
print(df['Order Date'].dtype)   # → object (string)
⚠️
The silent day-month swap bug

Our data uses DD-MM-YYYY (day first). Without a format= argument, Pandas defaults to MM-DD-YYYY. So "03-11-2015" becomes 11 March 2015 — no error raised, just a wrong date. Always use an explicit format string.

# ✓ Correct — explicit format, no ambiguity
df['Order Date'] = pd.to_datetime(df['Order Date'], format='%d-%m-%Y')
print(df['Order Date'].dtype)   # → datetime64[us]

The .dt Accessor — unlock date components

Once a column is datetime, .dt gives you every calendar property as a new column, ready for groupby.

df['Year']    = df['Order Date'].dt.year
df['Month']   = df['Order Date'].dt.month
df['Quarter'] = df['Order Date'].dt.quarter
df['DayName'] = df['Order Date'].dt.day_name()

02
DatetimeIndex & Time-based Slicing

"Set the date as your index, and Pandas hands you a time machine for your data."

Moving the date column into the index unlocks .loc['2016'], .loc['2016-Q1'], and all resample/rolling methods. Without it, you need a boolean mask every time.

df = df.set_index('Order Date').sort_index()
print(type(df.index))   # → pandas.DatetimeIndex
# Full year
df_2016  = df.loc['2016-01-01':'2016-12-31']
# Quarter
q1_2016  = df.loc['2016-01-01':'2016-03-31']
# Shorthand — entire year
year2017 = df.loc['2017']
⚠️
Always use .loc for date access

df['2016'] raises a KeyError — Pandas treats '2016' as a column name lookup. Only df.loc['2016'] does year-based row selection.

SQLPandas (DatetimeIndex)
WHERE date BETWEEN '2016-01-01' AND '2016-12-31'df.loc['2016-01-01':'2016-12-31']
WHERE date BETWEEN '2016-01-01' AND '2016-03-31'df.loc['2016-01-01':'2016-03-31']
WHERE YEAR(date) = 2017df.loc['2017']
03
Resampling by Period

"resample() is GROUP BY YEAR/MONTH compressed into one method call."

resample() groups every row by which calendar bucket it falls into, then applies an aggregation. It requires a DatetimeIndex.

daily_sales    = df['Sales'].resample('D').sum()
weekly_sales   = df['Sales'].resample('W').sum()
monthly_sales  = df['Sales'].resample('ME').sum()
quarterly_sales= df['Sales'].resample('QE').sum()
⚠️
Pandas 2.2+ alias change

'M' and 'Q' are deprecated. Use 'ME' (month-end) and 'QE' (quarter-end). Using the old aliases raises a FutureWarning.

SQLPandas resample
GROUP BY YEAR(date), MONTH(date)resample('ME').sum()
GROUP BY YEAR(date), QUARTER(date)resample('QE').sum()
Daily totalsresample('D').sum()
Weekly totalsresample('W').sum()

04
Rolling Window Averages

"rolling() is a sliding window that smooths noise so trends become visible."

The VP asked to "smooth out the noise" on the daily chart. A rolling average replaces each point with the mean of the N days before it, turning a jagged line into a readable trend.

daily   = df['Sales'].resample('D').sum()   # zero-filled by default
roll_7  = daily.rolling(7).mean()           # 7-day window
roll_30 = daily.rolling(30).mean()          # 30-day window
⚠️
First N-1 values are NaN

rolling(7) needs 7 days before it can compute the first average — rows 0–5 are NaN, first valid result at row 6. Add min_periods=1 for partial averages (SQL-matching behaviour).

05
Period-over-Period Comparisons

"shift(1) is LAG(1) from SQL. pct_change() is the formula every analyst uses for MoM growth."

shift() — the LAG function

shift(1) moves every value down by one row — giving you the previous period's number alongside the current one. The foundation of all period-over-period analysis.

monthly = df['Sales'].resample('ME').sum()

monthly_df = pd.DataFrame({
    'sales':      monthly,
    'prev_month': monthly.shift(1),  # LAG(1)
})
OUTPUT (head 4)
sales prev_month Order Date 2015-01-31 20496.37 NaN 2015-02-28 15389.83 20496.37 2015-03-31 39400.19 15389.83 2015-04-30 53633.35 39400.19

pct_change() — MoM and YoY

pct_change() computes the % change vs N periods ago. periods=12 on monthly data = same month last year (YoY). periods=4 on quarterly data = same quarter last year.

mom = monthly.pct_change()          * 100  # MoM %
yoy = monthly.pct_change(periods=12) * 100  # YoY %
qoq_yoy = df['Sales'].resample('QE').sum() \
                      .pct_change(periods=4) * 100  # QoQ YoY %
CallCompares each row to…Name
pct_change()1 row backMonth-over-Month (on monthly data)
pct_change(periods=12)12 rows backYear-over-Year (on monthly data)
pct_change(periods=4)4 rows backSame-quarter last year (on quarterly data)
shift(1)1 row back (LAG 1)Previous period raw value
🔦
The seasonality trap — compare like with like

December sales dropping 15% vs last December looks alarming — until you check the pivot table and see November and December always peak, January always crashes. That MoM drop from December to January every year is the calendar, not the business. The right comparison for Q1 2019 is not last December — it is Q1 2018.

SQLPandas
LAG(total_sales, 1) OVER (ORDER BY month)monthly.shift(1)
LEAD(total_sales, 1) OVER (ORDER BY month)monthly.shift(-1)

Fill Strategies for Time Series Gaps

"Missing values in time series aren't random — they carry context. The right fill preserves it."

resample('D').sum() silently zero-fills days with no orders by default. Add min_count=1 to get NaN for empty days instead — then you can decide how to treat them.

# Default: zero-filled
daily_zero = df['Sales'].resample('D').sum()

# With min_count=1: NaN for days with no orders
daily = df['Sales'].resample('D').sum(min_count=1)
print(daily.isna().sum())   # → 16 missing days over 4 years
MethodWhat it doesUse when…
ffill()Carry the last known value forwardPrice data, sensor readings — the last state persists until updated
bfill()Use the next known value backwardWhen future data is already available (back-filling a historic series)
fillna(0)Fill with zero — explicit "no orders"Revenue / orders: no order = zero revenue, not missing
interpolate(method='time')Estimate a gradual transition between neighboursSensor readings, temperature, continuous signals
